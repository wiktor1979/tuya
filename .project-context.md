# Projekt: Tuya Heat Pump Monitor
## Lokalizacja: C:\tuya
## Repo: GitHub (git skonfigurowany, remote istnieje)
## Deploy: Fly.io (app: 'scop', region: arn/ams, 1GB RAM, shared CPU)

## Opis
Aplikacja monitorująca pompę ciepła przez Tuya Pulsar (EU). Dwa procesy:
- main.py — zbieracz danych z Tuya + wątek pogodowy (Open-Meteo co 1h)
- dashboard.py — Streamlit dashboard (port 8501)

## Stack technologiczny
- Python 3.11 (Dockerfile: python:3.11-slim)
- Streamlit + Plotly (dashboard)
- SQLite z WAL, connection pooling, indeksy (baza: /data/tuya_telemetry.db na woluminie Fly.io)
- Tuya Pulsar + PyCryptodome (AES-GCM/ECB deszyfrowanie)
- streamlit-autorefresh (dynamiczny interwał: 60s gdy pompa pracuje, 300s gdy stoi)

### SCOP realny z defrostem
- P_th_kw_raw — surowa moc cieplna (zachowuje ujemne wartości)
- P_th_defrost_kw — strata cieplna defrostu (< 0 gdy defrost=True i ΔT < 0)
- E_th_defrost_kwh / E_el_defrost_kwh — energia defrostu
- SCOP realny = (E_th_nominal + E_th_defrost) / E_el_total
- compute_scop_metrics zwraca: scop_total (nominalny), scop_real, e_th_defrost, e_el_defrost, defrost_loss_pct
- compute_daily_stats: SCOP_realny dzienny, agregacja strat defrostu
- tab_scop.py: 4 KPI (nominalny, realny, CO, CWU), sekcja strat defrostu, tabela z SCOP nom./real.

### Próg opłacalności SCOP 3.1
- Linia referencyjna na wykresie COP chwilowy (pomarańczowa)
- KPI "SCOP Realny" z oceną vs próg 3.1 (zielony ✓ / czerwony ✗)
- Wykres SCOP dzienny: słupki SCOP realny (kolorowane zielono/czerwono wg progu), linia SCOP nominalny
- Filtr: dni bez pracy sprężarki (dt_hours_work == 0) wykluczane z wykresu i alertów
- Tekst: "mniej opłacalna niż ogrzewanie gazowe" (nie elektryczne)

### Alerty wydajności
- Zmienione z COP chwilowego na SCOP dzienny realny
- Filtr: dt_hours_work > 0 (pompa musiała grzać)
- Severity: 🚨 error gdy SCOP < 2.5, ⚠️ warning gdy 2.5-3.1
- Kontekst: data, SCOP, śr. temp. zewn., liczba defrostów
